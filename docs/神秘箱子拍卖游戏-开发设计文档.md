# 神秘箱子拍卖游戏 - 开发设计文档

## 1. 概览与范围
### 1.1 目标
- 落地 V1 核心玩法：房间系统、箱子生成、拍卖流程、结算展示、基础技能与技能卡。
- 支持 2-4 人多人在线匹配/私房邀请的完整流程。

### 1.2 范围约束（V1）
- 不包含好友/排行榜/成就等社交功能（V1.2）。
- 不包含技能卡商城复杂运营策略（V1.1）。
- 不做复杂美术资源与动画，仅满足基础展示与提示。

### 1.3 术语表
- 箱子（Box）：本局拍卖的物品集合与布局容器。
- 物品（Item）：箱子内可拍卖的单个物品。
- 拍卖（Auction）：多轮出价的竞价过程。
- 回合（Round）：拍卖的第 1-5 轮出价。
- 起拍价（Starting Price）：基于已揭示品质的均价计算。
- 填充密度（Fill Rate）：箱子中被物品占用的面积比例。

## 2. 系统架构
### 2.1 组件
- 前端：微信小程序（game-miniapp）
- 后端：SpringBoot（game-server）
- 数据库：MySQL
- 缓存与并发控制：Redis（锁、出价并发控制）

### 2.2 依赖与链路
- 小程序调用 REST API 进行房间、拍卖、技能等操作。
- 核心出价与成交逻辑在后端完成，前端只负责展示与交互。

## 3. 业务流程
### 3.1 房间生命周期
1. 创建/加入房间
2. 等待 2-4 人满员
3. 生成箱子与起拍价
4. 拍卖流程
5. 结算与结束

### 3.2 拍卖流程
- 最多 5 轮竞价
- 每轮出价或超时放弃
- 满足成交条件则结束，进入结算

### 3.3 结算流程
- 确定赢家与成交价
- 赢家扣款、物品入库
- 计算围观奖励
- 显示箱子完整信息与收益

## 4. 数据模型与表设计
### 4.1 核心表
- t_room（房间）
- t_auction（拍卖）
- t_bid（出价）
- t_box（箱子）
- t_item（物品）
- t_user（用户）
- t_inventory（仓库）
- t_skill_card（技能卡定义）
- t_user_skill（用户技能卡实例）

### 4.2 关键字段建议
- t_room: status, owner_id, max_players, current_players
- t_auction: current_round, status, winner_id, final_price
- t_bid: round, amount, is_valid
- t_box: width, height, fill_rate, total_value, starting_price
- t_item: quality, value, width, height, position_x, position_y

## 5. 箱子生成与物品放置算法
### 5.1 输入
- 箱子宽高：20 x 100-150（随机）
- 填充密度：50%-90%（随机）
- 物品尺寸：1x1 ~ 4x4

### 5.2 目标
- 大件优先，小件补空
- 上半箱子优先覆盖
- 保持随机性与可控密度

## 6. 拍卖与竞价规则实现
### 6.1 成交条件
- 第 1-4 轮按倍率条件判断
- 第 5 轮最高价成交

### 6.2 出价校验
- 最低加价：不低于起拍价 5%
- 超时未出价：判定放弃
- 出价冻结金额，放弃或被超价解冻

### 6.3 状态流转
- WAITING -> IN_PROGRESS -> SETTLEMENT -> FINISHED

## 7. 技能系统
### 7.1 基础技能
- 开局揭示品质/价值范围/密度等信息

### 7.2 技能卡
- 每轮最多使用 1 张
- 同一技能卡每局只可使用一次

## 8. 接口设计与契约
### 8.1 房间
- POST /api/v1/rooms/create
- POST /api/v1/rooms/join
- GET  /api/v1/rooms/{roomId}
- POST /api/v1/rooms/leave

### 8.2 拍卖
- GET  /api/v1/auctions/{auctionId}
- POST /api/v1/auctions/bid
- GET  /api/v1/auctions/{auctionId}/result

### 8.3 箱子
- GET /api/v1/boxes/{boxId}
- GET /api/v1/boxes/{boxId}/revealed

### 8.4 用户/仓库
- GET  /api/v1/users/profile
- GET  /api/v1/users/warehouse
- POST /api/v1/users/warehouse/sell

### 8.5 技能卡/商城
- GET  /api/v1/users/skill-cards
- POST /api/v1/skill-cards/use
- GET  /api/v1/shop/skill-cards
- POST /api/v1/shop/buy

## 9. 前端页面与交互
- 大厅：房间列表/匹配
- 房间：玩家列表/状态
- 拍卖：出价与技能卡操作
- 结算：缓慢揭示/跳过
- 仓库：物品列表/一键售卖

## 10. 并发与一致性
- 出价并发控制：Redis 分布式锁或 DB 行锁
- 成交判定与扣款在事务内完成
- 幂等校验：同一轮出价请求去重

## 11. 配置与运维
- 环境变量：DB、Redis、WX、JWT
- 日志：关键拍卖与出价日志

## 12. 测试计划
- 单元测试：箱子生成、出价校验
- 集成测试：完整拍卖流程
- 边界测试：超时、多人并发出价

## 13. 开发计划（V1）
### 13.1 阶段拆解
- 阶段 0：准备与对齐（0.5-1 天）
  - 产出：需求澄清清单、术语表、风险清单
  - 说明：保证范围边界清晰，避免 YAGNI 与返工
- 阶段 1：数据模型与基础设施（1-2 天）
  - 任务：设计表结构、状态机、索引；初始化物品库/品质均价
  - 产出：DDL、实体类、初始化脚本
- 阶段 2：房间与拍卖核心流程（2-4 天）
  - 任务：房间创建/加入/离开；拍卖状态机；多轮出价规则
  - 产出：核心 Service + Controller、接口文档
- 阶段 3：箱子生成与揭示逻辑（2-3 天）
  - 任务：箱子尺寸/密度/物品池生成；起拍价计算；揭示信息
  - 产出：生成算法实现 + 单元测试
- 阶段 4：结算与仓库（2-3 天）
  - 任务：成交结算、收益计算、围观奖励；仓库入库/售卖
  - 产出：结算 Service、仓库 API
- 阶段 5：技能与技能卡（2-3 天）
  - 任务：基础技能注入开局信息；技能卡使用与限制
  - 产出：技能效果框架、技能卡接口
- 阶段 6：小程序页面与交互（3-5 天）
  - 任务：大厅/房间/拍卖/结算/仓库页面；倒计时与揭示动画
  - 产出：页面原型 + 实现
- 阶段 7：并发与一致性（1-2 天）
  - 任务：出价并发控制（Redis 锁/DB 锁）；幂等去重
  - 产出：并发控制方案实现
- 阶段 8：测试与验收（2-3 天）
  - 任务：单元/集成测试；边界测试（超时、断线重连）
  - 产出：测试报告、问题清单与修复

### 13.2 里程碑与交付物
- M1：完成数据模型 + 核心流程 API（阶段 1-2）
- M2：完成箱子生成 + 结算闭环（阶段 3-4）
- M3：完成技能系统 + 小程序主流程（阶段 5-6）
- M4：通过并发与测试验收（阶段 7-8）

### 13.3 风险与对策
- 规则复杂度高：先固化 V1 规则，后续版本配置化
- 并发竞价冲突：锁与事务结合，保证成交原子性
- 箱子生成性能：必要时引入预生成/缓存策略
